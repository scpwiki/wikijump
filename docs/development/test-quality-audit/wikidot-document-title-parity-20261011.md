# Browser document-title compatibility — #2330 (2026-10-11)

Two **independent Wikidot** sources establish the visible page-tab delimiter for the SCP-Wiki page route; this is about observed behavior, not modern HTML style preferences.

1. `https://scp-wiki.wikidot.com/theme:yossistyle`: direct, read-only 2026-10-11 Chromium, Firefox, WebKit, and mobile Chromium capture, HTTP 200, `document.title = "YOSSISTYLE CSS THEME - SCP Foundation"`. Raw source observation and its SHA-256 (`632948f633aea578b55225958521c1f2607e17be2f4db811be08e`) are retained in `docs/development/test-quality-audit/yossistyle-same-source-20261011/live-wikidot-observation.json`. Same-source local browser capture instead saw `YOSSISTYLE CSS THEME | SCP Foundation` on all four engines. Source provenance, comparison and limitations are documented with those artifacts.
2. `https://scp-wiki.wikidot.com/scp-9506`: a **separate** 200 response retained in the operator-owned exact public response cache, cache identity `standing-live-chrome154-8037-97-aea09d69ce7f24d5-v17-82468c45f930` (`$HOME/.cache/wikijump-verification/standing-live-reference-chrome154-policy-v17-20261009/manifest.json`, HTTP Date `2026-10-09 00:27:01 GMT`). The response body SHA-256 is `3e3762a19945b3f314f7b0118acd626ac605fbb40698b1637ff5d9f117fb8d42`. Its actual HTML head contains `<title>National Fog Safety Initiative - SCP Foundation</title>`. A new read-only Chromium probe on the local standing mirror, `2026-10-11 14:57 JST`, returned HTTP 200 and `National Fog Safety Initiative | SCP Foundation` after hydration. The visible `#page-title` was `National Fog Safety Initiative`.

**Additional temporal mismatch:** on local standing, the response document for `theme:yossistyle` initially contains only `<title>SCP Foundation</title>`; observed browser `document.title` immediately after DOMContentLoaded was site-only for both pages, and became `page | site` after about 1 second. Wikidot's retained `scp-9506` HTTP response has the complete page title at parse time. The local application created competing `<title>` writers: `+layout.svelte` site-only SSR and a client-updating `<title>` in `PageHead.svelte`.

## Fix scope

The common layout now owns the document title both in SSR and after navigation, adding `page + ' - ' + site` **only for imported Wikidot page routes**, while local-native pages keep `page + ' | ' + site`. The descendant page component no longer adds a competing title. This does not alter visible `#page-title`, external page source, stylesheet, or underlying theme.

The hermetic HTTPS regression `framerail/tests/wikidot-document-title-https.spec.ts` checks that **both initial response HTML and hydrated tab title, and explicitly checks client-side navigation from a native fixture page to an imported one** follow the applicable imported/native boundary in Chromium, Firefox, WebKit, and mobile Chromium. The historical synthetic Yossistyle fixture is *not* mistaken for the current live Wikidot page; its explicit imported `wikidot-login-probe` counterpart tests the proven delimiter rule. Existing HTTPS typography browser checks remain unchanged.
